# 交易一致性与接口

## 固定事务边界

所有写操作从有效会话获得操作者，不接受客户端传入的角色作为授权依据。涉及商品和预约时统一先锁商品行，再锁该商品关联的预约行，以固定顺序减少死锁。READ COMMITTED下在行锁后重新检查状态。预约再用“product_id上仅有效状态唯一”的部分唯一索引兜底。跨表一致性由应用服务事务保证，普通CHECK不能直接代替跨表业务约束。

预约价格从锁定后的商品行读取，不信任客户端报价；成功日志、预约、商品状态及请求结果一起提交。写到一半发生错误时整体回滚；再使用独立事务写失败AuditLog，不记密码、令牌或原始敏感参数。日志落盘失败应报警，后续实现需要补偿机制，本设计不声称已运行。

## 幂等与重试

按(user_id, action, request_key)识别请求，保存规范化参数摘要、原响应、预约编号与expires_at，至少24小时。并发插入同键的请求等待首个请求提交后核对参数；相同参数返回原业务结果并附当前业务状态。旧请求已取消后只返回原结果与当前“已取消”，绝不能触发重新预约。用户主动再预约必须新建请求键。过期可清理请求结果，但不绕过当前状态和有效预约唯一性。

## 冲突顺序

卖家确认与买家取消：先取得商品锁并完成合法转换的事务生效；后到请求重新读状态并失败。管理员强制下架与买家完成同理：先下架则关闭预约，完成请求失败；先完成则保留成交事实，处置改为追加违规记录。取消、拒绝、关闭、完成是预约终态，不支持恢复。

## 主要接口

| 方法与路径 | 用途与校验 |
|---|---|
| POST /auth/register；POST /auth/login；DELETE /auth/session | 注册、登录、退出；不开放普通注册为管理员 |
| GET /products | 组合筛选、稳定排序及分页；公开仅已发布 |
| POST /products；PATCH /products/{id}；POST /products/{id}/submit | 本人草稿或合法已发布修改；提交校验必填字段 |
| POST /products/{id}/reservations | 请求键必填；非本人、已发布、唯一有效预约 |
| POST /reservations/{id}/cancel-or-reject | 买家取消或卖家拒绝；只允许待卖家确认 |
| POST /reservations/{id}/seller-confirm；POST /reservations/{id}/complete | 分别限定商品卖家与预约买家 |
| POST /reservations/{id}/close-requests | 仅交易参与人申请，管理员另行决定 |
| POST /products/{id}/reports | 非本人商品；同人同商品仅一条待处理举报 |
| POST /admin/reviews/{id}/decision；POST /admin/products/{id}/moderate | 审核与违规处置；原因不能为空 |
| GET /admin/audit-logs；GET /admin/statistics | 管理员组合筛选；日志不可普通改删 |

接口返回业务编号、当前状态与可操作项；失败含错误码、原因和刷新提示。参考状态码401未登录、403越权、409状态或请求键冲突、422字段不合法。HTTP设计不改变实验一需求。

## 统计与性能

首次发布按product.first_published_at；成交按reservation.completed_at和price_snapshot，预约编号去重。北京时间区间转为UTC左闭右开查询，金额按decimal核算。商品索引优先覆盖(status, category_id, price, id)和发布时间；关键词模糊检索初期评估ILIKE，必要时增加pg_trgm索引。索引方案须通过REQ-021约定的100次查询验收，不以图示替代实测。
