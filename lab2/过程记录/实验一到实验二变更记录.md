# 实验一到实验二变更记录

仓库沿用https://github.com/ghost-register/software-engineering-lab1，实验二在lab2-design分支的lab2目录中保存。实验一固定标签不移动、不覆盖。

## 用户的版本管理要求

用户原文：“在实验二中提到的git仓库沿用实验1的仓库，在遇到因为实验二过程中需要修改实验一内容时所做的修改也要记录在git中”。

执行规则：若出现业务需求变化，同一次变更中修改根目录requirements.md、设计追踪和本记录，写清需求编号、原内容、新内容、原因与影响，再单独提交。只细化设计时保留实验一原需求，不为了增加差异硬改业务规则。

## 当前检查结论

| 需求 | 实验二细化 | 是否改变实验一业务含义 |
|---|---|---|
| REQ-001、003 | 一个普通账号兼任买卖角色，管理员独立后台 | 否，沿用原角色及权限 |
| REQ-009、010、018 | 请求结果实体、部分唯一索引和商品行锁 | 否，是对唯一预约和幂等的实现设计 |
| REQ-011、017、024 | 用户要求取消放到详情，列表只查看 | 否，保留取消条件，只调整入口 |
| REQ-014、016 | 管理员异常关闭、违规下架与成交竞争处理 | 否，按原有状态规则细化事务 |
| REQ-019、020 | 失败日志独立提交、首次发布时间与成交快照统计 | 否，落实原审计与统计口径 |

截至当前阶段，没有必须修改实验一业务需求的变化。若后续用户提出新规则，再按上述流程记录和提交。
